# 体育高考训练助手（MVP）

面向**体育高考**（100米、立定三级跳远、原地推铅球）考生的 AI 周期化训练计划工具。
教练录入学生档案、目标成绩与测试成绩后，系统会自动：
1. **诊断短板**（如：起跑加速弱 / 后程掉速 / 三级跳第二跳衔接差 / 铅球用力顺序问题 / 下肢爆发力不足）；
2. 按 **考试日期倒推周期**（基础期 → 强化期 → 专项期 → 赛前调整）；
3. 生成**以周为单位的详细训练课表**（含动作、组次、强度、间歇、技术要点），支持 4/5/6 练每周；
4. 可**打印 / 导出 PDF**、教练在线修改备注后**确认定稿**。

> 系统有**两个入口**：教练端 `/login`（管理全部学生），学生个人版 `/s/login`（每个学生用教练发的**访问码**登录，只看到自己的计划并打卡）。
>
> 当前版本为**单教练本地版 MVP**（SQLite），后续可平滑升级为多教练 + PostgreSQL/Supabase 云端版。

## 技术栈

| 层 | 选择 |
|---|---|
| 前端 / 后端 | Next.js 15 (App Router) + React 19 + TypeScript |
| 样式 | Tailwind CSS |
| 数据库 | SQLite（`@libsql/client`，进程内、零配置、无原生引擎下载） |
| 认证 | 邮箱 + 密码（bcryptjs）+ JWT Cookie（jose） |
| AI（可选） | OpenAI 兼容接口润色（未配置密钥时由内置“训练科学引擎”完整生成） |

所有训练计划内容由**可解释的规则引擎**生成（周期划分、课表、诊断逻辑都在代码里，可审查、可修改），大模型仅作可选润色，避免“AI 瞎编强度”。

## 目录结构

```

    db.ts / repo.ts         # 数据库连接 + 类型化仓储（SQL）

```

## 快速开始（本地运行）

前置：需要 Node.js 18+ 与 pnpm（本机无 Node 时可使用 Codex 桌面端自带运行时）。

```bash
# 1. 安装依赖（使用国内 npmmirror 镜像，见 .npmrc）
pnpm install

# 2.（可选）初始化示例数据：默认教练账号 + 示例学生“李明”
pnpm db:seed

# 3. 启动开发服务器
pnpm dev
# 打开 http://localhost:3000

# 生产模式
pnpm build && pnpm start
```

### 默认账号（来自 seed）

- 邮箱：`coach@tiku.local`
- 密码：`coach123456`

> ⚠️ 上线/给他人使用前，请先修改默认教练密码，或通过数据库增加自己的账号。
> 配置项见 `.env.example`：`SESSION_SECRET` 请改成一段足够长的随机字符串。

### 使用流程（建议顺序）

1. 「添加学生」填写档案（重点填：**体育高考日期**、身高体重、训练年限、伤病史）；
2. 在学生页设置 **三项目标成绩**（按你所在省份的体育高考评分标准填写）；
3. **录入最近一次测试成绩**（100米建议同场加测 30m / 60m，便于拆分短板）；
4. 点击 **“生成训练计划”**，选择每周训练次数；
5. 查看计划 → 在“教练备注”中按实际情况修改 → **确认计划（定稿）** → 打印/导出 PDF 发给学生；
6. 每阶段末复测并把新成绩录入系统，重新生成下一周期计划；
7. **计划不是一成不变的**：学生状态变化（新成绩 / 伤病 / 疲劳 / 考试日期调整）时，在计划页点 **“按最新状态重新生成”**——系统会重新诊断、重排周期并回到草稿，确认后再发给学生（可顺带填写“最近状态”说明，会写进执行要点）。

## 学生个人版（让学生自己练）

适合“教练没法天天盯着”的学生：教练给他一个**访问码**，他自己打开手机/电脑登录即可。

### 教练操作

1. 进入学生档案 → “学生个人版”卡片 → 点 **生成访问码**；
2. 把 **访问码** 和学生入口地址（`/s/login`）单独发给该学生；
3. 想停用就点 **关闭学生访问**（学生再登录会失效）。

### 学生能看到/能做什么（极简）

- 登录后先选“每周哪几天训练”（必须等于计划的每周次数）；
- 首页大卡片显示**今天练什么**：课名、时长、每个动作的组次/强度/要点；
- 练完点 **“练完了，打卡 ✓”**（可撤销）；
- “本周安排”可点开任意一天查看内容；休息日会提示恢复建议；
- 顶部显示当前所处阶段（基础期/强化期…）与距考试周数，以及三项目标成绩。

学生看不到任何其他学生或教练管理功能。

## 训练科学说明（生成逻辑）

- **周期化**：按考试日期倒推剩余周数，切分为 基础期 → 强化期 → 专项期 → 赛前调整；
  时间不足时自动压缩为 强化冲刺 → 赛前调整；未设考试日期默认按 12 周。
- **周结构**：速度/加速、下肢力量、速度耐力、跳跃专项、全身力量+铅球、综合/测验 六类课循环，
  保证三项考试项目每周都被覆盖；选择 4/5 练时自动裁剪并保留关键课。
- **个人化**：诊断引擎给出 9 个维度的弱点权重（起跑加速、最大速度、后程耐力、下肢爆发、
  三级跳技术、投掷爆发、铅球技术、基础力量、核心），最高弱点会自动注入“弱点补强课”。
- **安全**：内置热身/整理放松、渐进超负荷（每周增幅 ≤10%）、疼痛即停、强度间隔等提醒。
- **指标口径**：诊断使用的比例阈值（如 30m/100m、三级跳/立定跳）为**经验参考**而非官方评分表；
  请以你所在省份的考试标准设定目标成绩。

## 数据库与数据

- 本地数据库文件：`data/tiku.db`（首次启动自动建表，已被 `.gitignore` 忽略）。
- 重置数据：停止服务后删除 `data/tiku.db`，再执行 `pnpm db:seed`。
- 后续升级云数据库（Supabase/PostgreSQL）：数据访问集中在 `src/lib/repo.ts`（原生 SQL），
  把连接串换成 Postgres 并微调少量 SQL 即可；表结构已按多教练（`coach_id`）设计。

## 后续规划（对应你的设想）

1. **训练反馈闭环**：每次训练后打卡（完成度、RPE 疲劳、伤病）→ 复测成绩自动对比 → 供下一周期调整；
2. **大班课**：同一计划多档分层（同课异构，按水平改强度/组数/负重），10+ 人班级一键生成；
3. **多教练多校**：注册/邀请 + 数据隔离 + 学校维度；
4. **数据沉淀与“AI 学习”**：匿名化的“画像→计划→效果”数据积累到一定量后，
   用统计归因固化为规则、用优质案例做参考（RAG），再考虑微调模型；视频动作分析（出手角度、三跳分解）作为远期亮点。
